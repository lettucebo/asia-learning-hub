## 執行與評分

- 每案開新對話。`FD-03` 的兩輪須在同一對話，依各輪的佐證評分。`FD-04` 使用獨立配置：保留候選版的指示詞、模型部署與工具設定，也保留同一批知識檔案，唯獨不提供 `recovery_policy.txt`。分開記錄隔離配置與檔案清單，不修改已儲存的候選版或其向量存放區。
- 檢查預期分流、指定的接手角色、必要佐證和禁止事項。在 Playground 比對回應詳細資料、來源註記或工具追蹤。需要訂單佐證時，必須確認檢索到精確的訂單紀錄；需要政策佐證時，必須確認檢索到指定段落。預期先澄清或缺少來源的案例，則檢查它有沒有明說缺什麼並依規定停止。
- 無法核對必要檢索證據、跨分支引用，或聲稱已執行沒有證據支持的動作、給出無法證實的結論，都算未通過。不得在相同對話重試後改算通過。若變更配置，記錄變更並對新的候選版重跑整套案例。

記錄案例 ID、輪次、UI 或 SDK、確切 agent 版本、模型部署（共用記錄使用別名）、實際分流、工具或來源佐證、禁止事項檢查、是否通過及驗證者。使用已清理的檔名和規則 ID，不附原始 trace。匯出前請另一位團隊成員重現入口網站設定及驗收。SDK 版比對同樣的情境和佐證條件，不要求回應逐字相同。

**實測狀態：** 操作指南記錄一次 v3 Playground 測試：擷取 21 案，4 案有差異，`FD-04` 未執行。尚未完成逐段檢索佐證核對或同儕驗證，因此不具匯出資格。
